## 3. THE TWO IT CANNOT YET ENFORCE — BEFORE IT IS DECLARED SATISFIED

**(a) That the action set IS the Identity-eligible universe.** The actions are built from
`consumptions` the caller supplies. Nothing reconciles that set against Identity's eligibility,
and `identity_eligible` appears in **0 files** at the ref. The output labels the population
`"population": "every Identity-eligible action"` — **a typed claim, not a computed one.**

The consequence is precise: the in-row fallback covers *"the challenger refused **at** an
action"*; it does not cover *"no action exists because nothing consumed"*. A decision point at
which nothing consumed is **absent from the score entirely**, not scored at Identity. Until
gate 5 produces the consumptions **and** something enumerates Identity-eligible decision points
independently, the guarantee the coordinator names rests on the caller's input, not on the
builder.

**And DE has already found the residual inside the guarantee, honestly:**

```
[PASS] where it ABSTAINS the challenger scores EXACTLY Identity -- it can avoid losing, never gain
[PASS]   and abstaining where it would be WRONG does improve the primary score
         -- §6 bounds that gain, it does not forbid it   abstain -0.2939 vs answer-both +0.5108
[PASS]   and the diagnostic intersection FLATTERS it, which is why it is not primary
         diagnostic -0.5878 vs primary -0.2939
```

So the property as the round states it — *"a challenger cannot improve by being ABSENT on hard
actions"* — is **not what the code delivers, and the code says so in a cell.** What it delivers
is: the challenger cannot gain **relative to Identity on a scored action**. Abstaining where it
would have been wrong still improves the primary score, because not being wrong is what
abstention is. **That gain is bounded by §8's 95% native-coverage gate, not by this scorer** —
and the coverage gate is therefore load-bearing in a way the plan's prose does not flag.

**(b) That the action is on the neutral Identity reference path.** `build_actions` reads the
caller's `on_identity_reference_path` flag and drops falsy rows with
`ACTION_IS_NOT_ON_THE_NEUTRAL_IDENTITY_REFERENCE_PATH`. **It cannot verify the path was
neutral** — rule 1's requirement (the unit is the decision-time exposure on the no-cancel
reference path) is asserted by the producer and trusted here. That is defensible layering, but
it means gate 4 cannot be *declared* to enforce it; gate 5 or 6 must, and whichever does needs
its own cell.

## 4. WHAT I WOULD ASK FOR BEFORE GATE 4 IS CALLED SATISFIED

1. **An eligibility join**: enumerate Identity-eligible decision points independently and
   refuse (or report by name) when the action set does not cover them. Without it the
   population label is prose.
2. **A cell for (b)** in whichever gate owns the reference path, so "neutral" is checked once
   rather than assumed twice.
3. **The coverage gate named as load-bearing** in §8's text, since it — not the scorer — is
   what bounds the abstention gain DE measured.

Everything else in gate 4 is done and driven, and the duplicate-key split and the
diagnostic-vs-primary separation are better than the plan asked for.
