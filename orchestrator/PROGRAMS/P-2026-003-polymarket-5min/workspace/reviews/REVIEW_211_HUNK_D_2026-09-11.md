```python

The attestation takes **precedence**. DE's claim is *"the pin makes the guard stronger, never
weaker"*, and that is true for days the code does not cover — but not for the nine it does:

```

**So a future attestation entry saying `2026-09-01: previously_opened_for "none"` would clear a

door on the guard that exists to hold rule 11.

**Inert today and I checked it rather than assuming:** DA's

## 4. ONCE v13 RESOLVES, IS THE ADMIT DIRECTION PROVABLE BY THE `dbb11e4` END-TO-END ALONE?

**No. It can supply at most half of one direction, and only with a check that is not currently
part of it.**

1. **It is the admit half only.** Rule 16: a control must fire *and* admit. An end-to-end that
   admits shows the arm said yes once. It cannot show the arm would say no to a
   **non-descendant**, to a **descendant with one build digest changed**, or to a **moved
   declaration sha**. Those three are the whole content of the rule; none is exercised by a
   book that satisfies it. An arm that has only ever said yes is precisely the control class
   this programme has caught repeatedly.
2. **Even the admit half is not self-attributing.** `_admissible_or_exact` returns a bool and
   records nothing about *which* arm admitted. The inference "it admitted ⇒ the descendant arm
   admitted" is valid **only if** the rebuilt receipt's `builder_commit` is verified to be
   `dbb11e4…` and therefore `!= PIPELINE_COMMIT`. That is an assertion on the receipt, not an
   output of the valuation — it must be made explicitly or the end-to-end is consistent with
   the exact-match arm having fired.
3. **It fails uninformatively in the other direction.** If it refuses, it refuses
   `BOOK_MISMATCH`, whose message names the builder and the frozen pipeline and says nothing
   about the declaration (REVIEW 210 §1). So a red end-to-end is not evidence about the arm
   either. It is a conjunction that cannot isolate the thing under test in **either** direction.

**What makes it provable**, and it is not much: the end-to-end **plus** four cells against the
same code path — descendant with matching digests **admits**; non-descendant **refuses**; one
declared digest changed **refuses**; declaration sha moved **refuses by its own name** — plus
the arm named in the record so a future reader can tell which one fired. Hunk D already shows
the shape: `_attested_day_read_state(decl_dir=…)` is injectable and anchors its file to the
passed directory. Give `_builder_commit_admissible` the same and all four cells become
writable today, before v13 lands.

**And the sequencing point for the coordinator:** the end-to-end is worth running for what it
does prove — that a book built off the pin survives the rest of the receipt check — but it
should not be read as licensing the descendant arm, and it should not be run as the *proof*
that v13 worked. The cheap check that v13 worked is `_declaration_pin()` returning a pin and
`_attested_day_read_state()` returning five days. Both are one line and neither needs a build.
