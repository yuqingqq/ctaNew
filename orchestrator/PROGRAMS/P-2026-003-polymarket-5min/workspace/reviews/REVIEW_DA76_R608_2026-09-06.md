## 0.1 **FINDING — row 8: the gate can be taken down by a malformed artifact instead of refusing it**

```python
_sup = rec.get("supersedes") or {}
sup_of[p] = {"path": _sup.get("path"), "sha256": _sup.get("sha256")}   # ← .get on a str
```

A `.v2` whose `supersedes` is a bare path string raises `AttributeError` out of
`find_sealed_day_receipt`, which `read_gate` calls **for every ruled day**. **Driven through
the full gate, not just the resolver:**

```
read_gate(params, now=…, root=…, ledger_rows=…) on a bare-string supersedes
  -> UNCAUGHT AttributeError: 'str' object has no attribute 'get'
```

The read aborts with a traceback rather than refusing by name — **one malformed artifact
takes the whole gate down.** DA anticipated exactly this shape and
says why: *"a bare path string is the PATH HALF of the pair, so it is an INCOMPLETE link and
refuses by name — reading it as a link would be resolving by name, which is what R-608
forbids."* DE's resolver never considered it.

**And nothing fixes the shape upstream:** `grep` finds **no `.v2` emitter in the runner** —
no site writes a `supersedes` block at all. The correction's shape is declared and resolvable
but not yet produced by any code, so what reaches the resolvers is whatever a hand or a
future emitter writes. One `isinstance(_sup, dict)` guard turns a crash into DA's refusal.

# 1. DA 76

## 1.1 The pair's definition is READ from DE's design, not typed — and that is the right answer

`supersession_pair_definition()` takes the form from DE's own design artifact
(`supersedes.chain` carrying two-element `[path, sha256]` entries) rather than hardcoding it,
with the reason stated at the source: *"reading it from the artifact means this verifier
cannot hold a different one than the seat whose links it is resolving — which is precisely
what REV 52 found."* That is a better fix than the one I proposed (declare the shape and check
both sides against it): it makes divergence **structurally impossible on DA's side** rather
than caught.

**The residual, and it is the mirror of row 8:** the binding is **one-way**. DE's resolver
types its own rule in code. If DE's design ever declared a different form, DA would follow the
design and DE would follow its literals — and the seats would part again with neither
noticing. A check on DE's side that its resolver's fields equal the design's declared entry
shape would close the loop.

## 1.2 The two refusals — both driven

Rows 3, 4 and 5 above are exactly them. **A half-written link is not "no link"** — DA states
the consequence precisely: reporting it as no-link "would make a half-written supersession
look like two independent runs", i.e. a botched correction would read as a day that ran
twice, which is a refusal for the wrong reason. And `SUPERSESSION_TARGET_DIGEST_MISMATCH`
reports the named file's **actual** digest beside the declared one.

## 1.3 §2.4 — the landing record: the four outcomes drive, and the digest is written twice

```
no record            -> NO_LANDING_RECORD
one record           -> ONE          head …20260906T100000Z.json
a CHAINED pair (.v2) -> CHAIN_HEAD   head …20260906T101000Z.v2.json   (the v2's digest)
two UNCHAINED        -> AMBIGUOUS    head None
```

The name is declared (`p003_da_gate1_pre_read_<YYYYMMDD>__<clock>.json`, with
`name_matches_convention` computed on the head), and **the day comes from the field, never the
filename** — driven: a file *named* `…_20260904__…` whose `day` field says `2026-09-03`
resolves for 09-03 and returns `NO_LANDING_RECORD` for 09-04. A record with no `day` field is
a named status (`LANDING_RECORD_NO_DAY_FIELD`) in `refused_records`, not a silent drop —
rule 11 at the seam.

**FINDING — the same digest is written twice and each seat reads a different copy.** DA's
pre-read emits `landing_record.receipt_sha256` (its own new field) **and** the older top-level
`receipt.sha256`. DE's conjunct-3 reader takes `receipt.sha256`; DA's takes
`landing_record.receipt_sha256`. Driven, with the two deliberately disagreeing:

```
landing_record.receipt_sha256 = aaaa…   receipt.sha256 = ffff…
   DA reads aaaaaaaa      DE reads ffffffff      neither complains
```

Today they are written from one `hashlib.sha256(rp.read_bytes())` call and agree. **Nothing
asserts that they must.** Conjunct 3 is the conjunct that stops a re-roll, and it resolves
through the copy DA does not check. One assertion in DA's emitter — or DE reading the declared
field — closes it.
