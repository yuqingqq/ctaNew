# 0. THE PIN FLIP — right in principle, and it resolves in neither direction

**The reasoning is correct and I would not have it reversed.** A digest pin can only run
from the artifact emitted LATER to the one emitted EARLIER; the design is emitted last
because it needs the code's carrying commit, so params-cites-design-by-digest forced a
params version whose only content was a pointer (v3→v4, v4→v5, and v6 would have been the
third). Flipping it is the right repair and the senior document holding the pin is the right
choice.

**Both sides of the flip are wrong at the artifacts. Driven:**

```
design v14 -> parameters.path   = live/pm_research/declarations/de_multiday_gate1_params_v2.json
   that file exists, digest      ce46b5775d8f17a4
   the digest v14 DECLARES       1af1befbbf0b496a   <- which is params **v6**
   (v2 ce46b577… | v5 306bfdb0… | v6 1af1befb…)

params v6 -> design_declaration.path = data/pm_5min/derived/p003_de_multiday_gate1_design_v14__<emitted this round>.json
   exists: False        sha256 field: "NOT_PINNED_HERE -- SEE THE NOTE"
   the real file on disk: p003_de_multiday_gate1_design_v14__20260906T091319Z.json
```

So the design pins **v6's bytes under v2's path** — path and digest naming different files —
and params points at a **template that was never filled**. This is DE's own documented
recurrence: `DECLARATION_CHAIN`'s comment says `supersedes.path` is the last element "never
a typed constant — that is how v7 came to name v2". **v14 names v2.**

**And it is not latent. Driven at the tip:**

```

  blocking = ["P2_book_exists", "P2_builder_receipt_exists", "P3_design"]
  P3_design: holds=false, blocks_go=true
    path     "…design_v14__<emitted this round>.json"
    declared "NOT_PINNED_HERE -- SEE THE NOTE"
    on_disk  null
  status: NOT_READY_P2_book_exists_P2_builder_receipt_exists_P3_design
```

The first two are expected — 09-04's book is not built. **`P3_design` is the flip.** The
09-04 run is the next thing to happen after the smoke lands, and its preflight refuses on a
pointer.

**The runner's 167 checks and the design's 89 both PASS while this is true** (my run). That

# 3. Rule 22 — it closes the instance and about a third of the class

**The class I named** (REV 49 §0): *any landing to the runner during a run rewrites that
run's provenance.* Rule 22 has two halves.

**The mechanical half — "Runners capture their source digest at import and refuse the emit
by name if the on-disk bytes have changed" — closes the class for ONE FILE of one runner.**
Verified: it works (§1.2), and it is implemented only in
`de_multiday_gate1_runner.py`. What it does not reach:

* **Sibling modules the run imported.** `de_multiday_design_declaration` is imported at
  module level and its bytes are never digested by the run at all. A landing to the design
  module mid-run changes the runner's behaviour on nothing and leaves **no trace anywhere**:
  the runner's own digest is unchanged and the design JSON is unchanged.
  `import_be_cascade` digests the cascade **by reading the file** after `import_module` has
  already returned a possibly-cached module — the same check-and-use window, one module over,
  narrow but of the identical shape.
* **The other seats' heavy producers — and this is the near-term one.**
  `be_daybook_build.py`, `be_gate1_fragment.py` and `be_gate1_state_tape.py` carry **zero**
  occurrences of `carrying_commit`, `producing_code`, or a `__file__` digest. They are the
  next three heavy runs (BE 58/59, 09-04, ~10/25/35 min each) in a period where seats land
  every few minutes — and **BE 59 is about to add the builder commit** R-601 asked for. If
  that field is stamped at emit, BE inherits the defect DE just fixed, on its first use.
  Rule 22 says "runners"; nothing makes it true of these.

**The practice half — "a worktree whose HEAD is not moved and whose files are not edited" —
has no enforcement at all.** Nothing reads HEAD at launch, nothing compares it at emit, and
the incident it was written for was caught by a human looking (R-603: DE's uncommitted edit
at 09:05:44Z, reversed at 09:09:48Z). A practice that depends on noticing is the thing the
programme has replaced with instruments eleven times this week.

**What would enforce it, and the pattern already exists here.** At import, capture (a) the
digest of every module in `sys.modules` whose `__file__` is under `live/pm_research/`, and
(b) the worktree's `HEAD` sha; at every emit, refuse by name if any moved. That is
`assert_source_unchanged` generalised from `__file__` to the import closure — and DA already
ships exactly this concept: its deploy record pins "both entry modules **and their import
closure** — seven files by DA's rule" (R-556). The runner is the right place because it
already owns the emit refusal; the launch wrapper can only add HEAD, and only if it writes
it somewhere the runner reads.
