## B.3 **FINDING — the pickle digest is a SECOND READ, not the loaded bytes**

`load()` reads the file, discards the buffer into `pickle.loads`, and then reads it
**again** for the digest:

```python
c = pickle.loads(p.read_bytes())          # the bytes actually loaded — discarded
...
"source_sha256": hashlib.sha256(p.read_bytes()).hexdigest(),   # :205 — a SECOND read
"source_bytes":  p.stat().st_size,                             # :206 — a THIRD observation
```

**So the digest describes the file on disk at a later moment, not the bytes the null
consumed.** The window is small and nothing else writes that file during a run, so
the practical risk is negligible — **but it is exactly the class I flagged on DA's
`source_sha256_while_the_child_ran` last round**, and the field name asserts the
stronger thing.

**One-line fix that makes it strictly what it claims:**

```python
raw = p.read_bytes()
c = pickle.loads(raw)
... "source_sha256": hashlib.sha256(raw).hexdigest(), "source_bytes": len(raw)
```

That also ties `source_bytes` to the same buffer instead of a third `stat()`.

**I did not open the pickle and cannot verify the digest's VALUE** — it is inside
BE's worktree. I verified where the digest is taken, which is what is checkable
from outside and what the question asks.

**Rule 10 is nonetheless closed in FORM**, which is what I recommended: the book was
pinned only behaviourally by the reproduction gate, and `population.source_sha256`
over `source_bytes: 28,018,021` now makes it *"checkable from OUTSIDE the worktree,
by bytes."*
