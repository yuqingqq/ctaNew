## 1.3 What the exit map can still hide

Driven (grep over the runner and its `live/` import closure — `be_cancel_axis_null`, `harmful_stateful_policy`, `de_phase4_diag_runner`, `be_data_root`, `da_root`, `be_rule22`): **no numeric exit ≥ 2 anywhere**; every `SystemExit` carries a string (Python exits **1**) or `main()`'s int. # 4. The three rule-20 guards (`c2a63e7`) — the words, and the property

**Guard 1, "a check that depends on the declaration FAILS when the file is absent — never skips."** Two ways to satisfy the words: (i) a check that **aborts the whole battery** rather than failing one cell — a suite that never reports is not a suite that reported a failure, and only an expected-count comparison (`EXPECTED_CHECKS`, which both DE and BE already have) tells them apart; (ii) **read a declaration that exists but is superseded** — which is the state of the tree right now (§3.1). The guard needs "the declaration" to mean *the chain head*, resolved, not a filename.

**Guard 2, "the check on a launcher reads the LAUNCHER'S BYTES."** `be_rule22.LAUNCHER` resolves relative to the importing module's own file — importing from `wt-rev` I got `/home/yuqing/ctaNew-wt-rev/live/pm_research/be_heavy_run.sh`. Four worktrees, one filename: a check can read *its own tree's* launcher while the unit runs with `--working-directory=<another worktree>`. The words are satisfied; the property ("the bytes the running unit executed") is not. The decidable version is the same as §1.2 — the unit's own `ExecStart`, or `/proc/<PPid>/cmdline` from inside.

**Guard 3, "grounded by exactly ONE DRIVE — a unit launched against a held lock, its ExecMainStatus read as 75."** Two gaps: the drive is necessarily run against a **scratch** lock (R-638's seam requires it), so it grounds *the conflict code's behaviour*, never *the declared `lock_path`* — a separate instrument (`wrapper_observed` by inode) grounds that, and the guard should say which claim it grounds. And the drive's payload must be one whose own exit codes exclude 75, or it proves nothing (§3.2 of REV 68); BE's sleeper qualifies, and the receipt should record the payload as well as the code. Finally, "named in the receipt" is a string: what belongs there is the **measured** triple and the `InvocationID` of the grounding drive.
