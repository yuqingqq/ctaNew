# 3. The poll — by unit, and the status read rather than assumed

Declared at the source: `"poll_by": "the UNIT name, never a child PID"`, and
`"read ExecMainStatus, never assume it started"`. `unit_identity()` also reports the run's own
`cgroup_leaf`, `kind` (`transient service` / `scope`) and `is_the_declared_launch_form`, so the
receipt can be asked *"scope or service?"* after the fact.

**One recommendation, not a GO condition.** `is_the_declared_launch_form` is **reported and
gates nothing**: a real day launched under `--scope` would run, be killable from outside, and
say so only in its receipt. The datum is measured from the process's own cgroup leaf, so the
guard is one line, and the asymmetry already exists next door (the dirty worktree is *recorded*
for a fixture and *refused* for a day). **For a real day, refuse when `kind == "scope"`** — it
closes the last outside-the-run kill path the run can see from inside.

**Closed, and closed the right way — by PROPERTY, never by name.** Driven, all four cells:


Both readings travel in the receipt (`dirty`, `dirty_beyond_the_shared_data_link`), so the
