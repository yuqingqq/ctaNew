# 3. The nightly unit's deploy drift — both halves, and rc 7 in the map

**Neither option alone is sufficient; they are two halves of one discipline.**

- **A pinned commit alone** lets the unit keep running last night's bytes while the seat improves the verifier — the nightly verdict silently drifts from the code the programme believes it runs.
- **Same-round re-deploy alone** lets the unit run whatever is in the tree at 00:06Z, including a half-landed change — the mid-run landing hazard rule 22 exists for, one level up.
- **Together:** the unit runs from a **pinned commit**; a landing that touches any pinned file **re-pins in the same round**; and the drift guard's refusal is what catches the seat who forgets. Tonight it did exactly that, wrote nothing, and cost a catch-up — which is the guard working, not failing.

**How it is checkable: the deploy pin as a declaration by pair**, through the CAS like every other family — `{unit, commit, files: [{path, sha256}], deployed_at}`. Then the guard compares current digests against the pin's, and — the part that is new — **a landing that changes a pinned file without a new deploy version becomes visible to the non-head census DA already runs**, instead of being discovered at 00:06Z by a refusal. The pin stops being state inside a unit and becomes an artifact, which is where everything else in this programme has moved this week.

**rc 7 belongs in the exit map, and it is the clearest case yet.** It is a *producer-declared verdict* — `DEPLOY_DRIFT`, nothing ran — the third kind beside the wrapper's 75 and the interpreter's 1. Undeclared, a reader at 00:06Z sees a failed unit and cannot tell *"the guard refused, nothing ran, the day is a catch-up"* from *"the verifier crashed"*, which are opposite facts about the night. Declare it in DA's block by pair; it is DA's second declared code after rc 3, and the map's `reading_kinds` already has the vocabulary.
