# 1. The porcelain halves — driven, and the falsifier's third line is the finding

DA's `parse_porcelain` is now *"the programme's ONE porcelain parser"*, imported by DA's
modules. Driven on the three-line block:

```
BLOCK = " M live/x.py\n?? data\nR  a -> b\n"

DA parser, raw          -> ['live/x.py', 'data', 'b']      malformed: []
DA parser, .strip()ed   -> ['data', 'b']                   malformed: ['M live/x.py']
raw + [3:]   (DE 96 / BE 64)  -> ['live/x.py', 'data', 'a -> b']
strip + [3:] (the defect)     -> ['ive/x.py',  'data', 'a -> b']
```

**Both halves are closed in DA**, and the parser does something neither half did alone: on a
damaged line it reports **`malformed`** rather than silently returning a short path. A caller
gets a named problem instead of `ive/x.py`.

## 1.1 **Will DE's and BE's remaining `[3:]` halves pass the same falsifier? On two lines out of three.**

* Line 1 (` M live/x.py`) — **pass** with a raw read: `[3:]` gives `live/x.py`.
* Line 2 (`?? data`) — **pass**.
* Line 3 (`R  a -> b`) — **FAIL.** `[3:]` returns **`a -> b`**; the path is `b`.

**A rename is not a hypothetical for these two readers.** Both consume porcelain to classify
dirt: DE's `_is_the_shared_data_link` and BE's `classify_dirt` would test
`islink(root/"a -> b")` → False → **real dirt**, and a real day would refuse on a rename with a
nonsense path in its message. Fail-safe in direction, wrong in cause, and the message would send
a reader looking for a file called `a -> b`.

So the answer to the question as posed: **as specified, the falsifier fails DE 96 and BE 64 on
its third line**, and it should — that line is why it has three. **The durable fix is the one
DA has already built:** import `parse_porcelain`. And by the argument I made in REV 65 §2, that
is R-235-safe — a porcelain parser is **infrastructure**, not a statistic; two implementations
of it corroborate nothing and are simply two places to get the format wrong, which is now
demonstrated three times (the strip, the slice, the rename).

# 2. The battery that could not see its own last checks — fixed, and **no other seat has the shape**

**DA's fix, verified at the source:** the count and the print now come after the last check,
with an assertion that the summary matches the list it summarises —

```python
recount = sum(1 for c in checks if not c.get("passed"))
assert recount == n_fail and len(checks) == len([c for c in checks if "check" in c]), \
    "the summary disagrees with the list it summarises"
print(f"\n{'SELFTEST OK' if not n_fail else 'SELFTEST FAILED'} -- {len(checks)} checks, {n_fail} failure(s)")
```

That is the right repair: not "move the print", but **make the summary check itself against the
list**, so the next time something is appended after it the assertion fires rather than the
count quietly under-reporting.
