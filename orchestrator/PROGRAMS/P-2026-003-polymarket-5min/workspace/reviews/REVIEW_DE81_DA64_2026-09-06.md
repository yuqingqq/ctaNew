# 1. DE 81 — THE FOUR REV 43 ITEMS

## 1.1 The digest now reaches the load — the mechanism, driven

```

PA.tape_index(split, features_in_order=None, *, path=None, day=None, expect_sha256=None)
   -> _tp = assert_tape_for_day(day, path, expect_sha256=expect_sha256)
   -> for r in _stream_tape_rows(Path(_tp["tape_path"])):
```

The check is inside the function that opens the stream, one statement before it.
Driven at `assert_tape_for_day`:

```
REFUSES  ruled day + WRONG expect_sha256                 [6.0s]  TapePathRefused
REFUSES  ruled day + the CONSUMED default path           [0.0s]  "…the DEFAULT (phase2_state_tape_v5.json)"
ADMITS   ruled day + right path + right digest           [0.6s]  digest_verified_at_load True
ADMITS   day=None, the consumed hour                     [0.0s]  unchanged
```

and at the load itself: `tape_index(..., expect_sha256="0"*64)` **refuses in 0.6 s** —
a fast refusal is the evidence it did not stream the 991 MB.

## 1.2 **FINDING — the digest comparison is a 16-hex prefix, and a one-character "digest" passes**

```python
if not got.startswith(expect_sha256.lower()[:16]):
    raise TapePathRefused(...)
```

**Equality is never tested.** Only the first 16 characters *of whatever the caller
passed* are compared — so a shorter string is a shorter check. Driven, all against the
real tape:

```
ADMITS   the REAL digest                             digest_verified_at_load True
ADMITS   first 16 hex RIGHT, the other 48 WRONG      digest_verified_at_load True
ADMITS   a 16-char stub                              digest_verified_at_load True
ADMITS   a ONE-character "digest"  (expect="9")      digest_verified_at_load True
REFUSES  the WRONG first 16
```

The receipt then records `digest_verified_at_load: True` — a verification that was
performed at whatever strength the caller's string happened to have, reported as
though it were the digest. A truncated or malformed pin **weakens the guard silently
instead of refusing**, which is the shape rule 11 names: absence must not read as a
pass.

**Fix, three lines:** refuse an `expect_sha256` that is not 64 lowercase hex
characters, and compare with `hmac.compare_digest(got, expect)`. If a 16-hex prefix is
ever legitimately declared (some receipts carry prefixes), accept it only when it is
labelled a prefix and record `n_hex_compared` beside the boolean.

## 1.3 **FINDING — the ruled-day-without-a-digest refusal cannot fire on BE's actual call**

Design v12's R16 states: *"AND_A_RULED_DAY_WITHOUT_expect_sha256_REFUSES"*. The guard
is real:

```python
if (tape_path is not None and expect_sha256 is None
        and day in _ruled_day_set_imported()):
    raise DiagRefused("… a tape path was supplied with NO expect_sha256 …")
```

**It turns on `day`.** And `be_daybook_build.py:406` calls:


— **no `day`, no `expect_sha256`.** So `day` is `None`, `None in ruled_set` is False,
the guard does not fire, `_kw` carries only the path, and
`assert_tape_for_day(None, path, expect_sha256=None)` applies neither the ruled-day
check nor the digest check. **The stream runs unverified.**

**This is how I found it, and I report the cost.** I drove exactly that call to see
whether it refuses. It did not — it began streaming the 991 MB tape and my drive was
**killed at 120 s**. I did not repeat it (BE 55 holds the lock and the stream is

**In BE's favour, and it matters:** BE *does* now call the front door —

**What is lost is the second check**, and design v12 itself says that is the point:

> `THE_DIGEST_IS_CHECKED_TWICE_AND_THAT_IS_THE_POINT` … *"the first leaves a window

BE gets check #1 and not check #2, while the design asserts both. **One keyword closes

the weaker of the two forms the design offers.
