## A.6 **FINDING — the stale-pycache hazard is real and the fix is NOT sufficient. Demonstrated, not argued.**

**The hazard is real and precisely characterised by DE:** the mutants replace
`0.5` with `0.0` — **the same byte length** — so with second-granularity mtime a
restored file can serve a stale `__pycache__`, because CPython's default `.pyc`
validation is exactly **(mtime, size)** and the mutation changes neither. DE hit
it once mid-round.

**`PYTHONDONTWRITEBYTECODE=1` does not close it.** I built the minimal case and
ran it:

```
def v(): return 0.5      -> import, .pyc written
sed 0.5 -> 0.0           (same byte length), mtime restored
PYTHONDONTWRITEBYTECODE=1 python3 -c "import m; print(m.v())"   ->  0.5
cat m.py                                                        ->  return 0.0
rm -rf __pycache__ ; same command                               ->  0.0
```

**The interpreter returned the OLD value while the source on disk held the new
one.** The variable suppresses **writing** bytecode; it does nothing about
**reading** a `.pyc` that already exists. The audit is protected from *leaving*
a stale cache and not from *finding* one.

**So yes — the harness should verify bytecode identity**, and there are three
fixes in increasing strength: (1) `rmtree(__pycache__)` per mutant — **the
pattern already exists in this repo at `be_forward_day.py:2903`**; (2) hash-based
invalidation (PEP 552 `checked-hash`), immune to mtime/size collision; (3) record
in the receipt which bytes the interpreter actually executed.

**Did the hazard contaminate the reported result? No, and it is worth saying
why.** A stale cache would have made DA's own suite go GREEN on a mutant — and it
went **red 4/4**, so those four are self-guarding. The only place it could have
masqueraded is the **consumer's 0/4** — and that result has an independent
structural explanation established last round (the pre-DE65 selftest asserted
nothing about `PA.compare`'s output, so 0/4 was guaranteed). **The finding stands
on its own evidence, and the hazard remains open for the next audit.**
