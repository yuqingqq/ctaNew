## Why: post hoc, after the readings

Script `research/pf_kp_s4_posthoc.py`, run 05:50Z on S4's out-of-fold predictions. It has no readings, and nothing in it is
validated on these days.

- **At the states the label describes, the predictions help.** Scored one decision at a time on the held-out never-pull rows (c/sh
  per row):

  | Rule or bin | Pulls at | One-step gain | Mean Delta | Share where pulling is right |
  |---|---|---|---|---|
  | KP, pull when predicted < 0 | 25% of rows | +0.052 | | |
  | G (v only), same rule | 9% of rows | +0.032 | | |
  | KPS, same rule | | +0.003 | | |
  | Perfect foresight | | +0.281 | | |
  | Bottom 1% of KP's predictions | | | -2.53 | 59% |
  | Bottom 20% of KP's predictions | | | -0.26 | 17% |
  | Top half of KP's predictions | | | +0.28 | |

- **On its own path, the policy churns.**
  - The model decides only for a resting order. The lane re-places the order 250 ms after every pull, which is the label's own pull
    path.
  - So while the predictions stay negative, the order is pulled, re-placed at the back of the queue, and pulled again: 122 pulls
    per side-minute. On 11-08 the perfect-foresight policy pulled 8.9.
  - The guard trigger instead keeps the order out while v <= -0.10, because the trigger also blocks re-placement. It trades 15% of
    never-pull's fills at -0.34 c/sh. KP trades 20% of them at -1.17.
  - The label prices "pull now and re-enter in 250 ms". It never prices staying out, and staying out is what makes the guard's arm
    lose less.
- **The random control is matched on planned pulls, not realised ones.**
  - Pulls are drawn at resting steps of the never-pull path. A drawn step where the random path's order is not resting is skipped.
  - So the draws realised 64.5% of KP's pulls (45,224 against 70,069 per day at M 50) and filled 3.6x KP's shares.
  - Per share they lost more than never pulling (-1.74 against -1.53 c/sh at M 50), while KP lost less (-1.17).
  - R261 fails on the guard condition either way.

## What it means

- The inputs contain information about keep against pull: skill on 9 of 9 days, a positive one-step gain, and a large margin over
  random pulls and over never pulling.
- The action set is wrong for a policy. Pulling with forced re-entry after 250 ms is not the action that makes the guard trigger
  lose less; staying out is.
- Nothing tested here beats v3, and nothing that rests by default is positive at any clock.

Next steps. Each is a proposal, none has been run, and the user decides:
- **S4b, add the stay-out action.** At each step without an order, label Q_enter_now - Q_wait (wait = decide again 250 ms later).
  Place only when the predicted entry value is >= 0; keep the pull model for resting orders. Same days, same controls, readings
  declared first.
- **Or gate v3 with the pull model:** v3 is the only positive arm, and the model could pull v3's resting orders. That is a
  different lane, and its fills are few (376-410 per day).
- **Either is exploratory on consumed days.** A pass makes a candidate for a freeze and a forward test on >= 5 untouched days after
  11-13 (design S5).

## Limits

- 9 consumed days, first 60 s of each window only.
- The replay fill model (rule M) is not validated (B1a).
- One 5-sh order per side, and our order is not in the public book.
- CAP10 / RO60 / MICRO / G4 and the Binance hard guards are not modelled.
- The guard value v on a training day comes from guard models whose fits included the held-out day (indirect leakage; the held-out
  day's own v is out of fold).
- The random null is matched on planned, not realised, pulls (see above).
